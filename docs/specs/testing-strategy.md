# Testing Strategy

## Test Types

- **Unit tests** — per-component correctness (a given open component or text-extraction component against a specific known input), independent of the DI container.
- **Integration tests** — both public functions end-to-end against every sample in the curated corpus (see `dataset-curation.md`), asserting exact expected format, exact expected text/metadata content (not just non-empty), and exact expected subfile list against the corpus manifest.
- **Time profiling** — a dedicated benchmark project measuring [ydk:nfr:extraction/extraction-latency] and [ydk:nfr:extraction/memory-ceiling] per format against fixed corpus samples (tooling choice recorded in ADR-002), run separately from the unit/integration suite.
- **Stress testing** — a concurrent-load harness (tooling choice and rationale recorded in ADR-002) exercising at least 50 concurrent calls to both public functions (configurable higher for extended runs), reporting throughput/latency/memory under load. Not part of the standard test suite gate — run manually or as a longer CI job.

## Rules

- **NEVER assert only "text is non-empty"** for a corpus sample that has an exact expected string recorded in the manifest — this is how truncation/mojibake bugs hide (see [ydk:req:extraction/unicode-fidelity]'s acceptance criteria).
- **NEVER assert a thrown error for a per-field failure case**, and never assert a no-value leaf without also asserting its field-error entry. Under [ydk:req:extraction/per-field-error-isolation] the adversarial cases that occur after the container opens — post-open corruption, a corrupt embedded object, an oversized nested item — assert a populated result plus a specific [ydk:entity:extraction/FieldError] at the exact field path, and assert that the document's other leaves are still populated. An empty extracted text with no field-error entry, or a short subfile list with no field-error entry, is a test failure: that silent-pass shape is the behavior this requirement removes, so a test that tolerates it removes the guard. The container-open cases (file-too-large, password-protected, invalid-password, unsupported-format, truncated-container, zero-byte, null request/field, and a container that cannot be opened at all) still assert the throw, and also assert that no result is returned, so the fatal set cannot drift into the per-field channel unnoticed.
- **NEVER mock the format-handling components** in integration tests — the whole point is exercising the real parsing path against real file bytes. Mocking is only appropriate at true external boundaries, and this library has none (no network calls, no filesystem dependency inside the extraction path itself — callers supply bytes).
- **Every adversarial-review scenario in `overview.md` that isn't explicitly marked out of scope MUST have a corresponding test** (the decimal/locale-precision bullet is explicitly out of scope and needs no test), via one of four mechanisms — a scenario not covered by one of these doesn't count as covered:
  - Corpus-sample-backed: corrupt, truncated, zero-byte, oversized, password-protected, wrong-extension, and corrupt-embedded-object (shared adversarial set); macro-variant-misclassification (each format's macro-enabled synthetic sample); deeply-nested embedding (the curated 2+-level-nesting sample) — all tagged in the corpus manifest.
  - Unit-test-backed (no checked-in sample needed): null request/field validation; file-too-large (a synthetic oversized byte-array length, per [ydk:nfr:extraction/max-file-size]'s test method); the crafted encryption inputs below.
  - Encrypted-sample-backed: wrong password, password on encrypted doc/ppt, password on an unencrypted file, decryption bomb (the encrypted set in `dataset-curation.md`).
  - Stress-harness-backed: concurrent calls on shared/different files.
- **Every password-protected sample in the encrypted set is tested three ways** under [ydk:req:extraction/password-decryption]: no password, wrong password and correct password. Two samples in that set are excluded, because they have no open password of their own: the xls encrypted only with Excel's default key (asserted to extract identically with no password and with an arbitrary one) and the document embedding an encrypted subfile (asserted to return that subfile opaque). A decryptable sample asserts [ydk:error:extraction/password-protected], [ydk:error:extraction/invalid-password] and a result equal leaf for leaf to its unencrypted twin's manifest expectations (file size excepted). Encrypted doc/ppt samples follow the same three ways ([ydk:req:extraction/legacy-decryption]). A negative-only sample (manifest `negativeOnly: true`, password unknown, see `dataset-curation.md`) asserts the first two only and never a decrypted result. An XOR-obfuscated doc (crafted by mutating a fixture copy) asserts [ydk:error:extraction/password-protected] with and without a password. A gated assertion, if one is ever needed, is marked as skipped with the blocking issue named, and it is never deleted. Detection is asserted the same three ways (Unknown, invalid-password, inner format for an encrypted package; the unchanged legacy format for encrypted doc/xls/ppt).
- **Encrypted samples come from `samples/encrypted/` only** (see `dataset-curation.md`). A test reads the password and the twin to compare against from the sample's manifest entry, never from a hard-coded constant, and finds encrypted samples by that folder rather than by name or marker.
- **Known decryption test gaps stay visible.** The gaps G1 to G5 of [ydk:req:extraction/legacy-decryption] are listed in the manifest's `$encryptedTestGaps` (shape in `dataset-curation.md`). A manifest schema test checks that every gap has an entry with the required fields, and an entry is never deleted except in the change that adds a real-fixture assertion for it.
- **Password ignored on unencrypted files.** Every unencrypted corpus sample of all six formats is also run with a non-empty password, and both detection and extraction must return exactly the no-password result: same detected format, same leaves, same field errors, nothing thrown. A test that only checks "no exception" does not count.
- **Password confidentiality** ([ydk:req:extraction/password-confidentiality]): every password-path test uses a distinctive sentinel password and asserts that it appears in no captured log line, no exception text or data, no field-error message and no serialized result.
- **Password concurrency** is unit-test-backed, not only stress-backed: concurrent xls extractions with different passwords (some with none) start together on a barrier with a bounded timeout, never on wall-clock overlap. Each must get its own correct outcome, and the per-thread password slot must be empty after every call.
- **Crafted encryption inputs** (key-derivation cost over the maximum, declared decrypted size over the cap or over the stream length) assert their error and, via a counter or spy, that no key derivation or decrypted-buffer allocation happened.
- **Crafted legacy encryption headers** ([ydk:req:extraction/legacy-encryption-header-bounds]) are made by mutating a copy of a doc/ppt fixture inside the test. Examples: a header length out of range, a bad key size or header size, an edit-chain cycle, a summary descriptor count of 0x7FFFFFFF. Each one asserts [ydk:error:extraction/corrupt-file] and asserts that the error is not [ydk:error:extraction/invalid-password], not out-of-memory and not a raw library exception.
- **Encrypted doc/ppt are never parsed before the guard.** A spy on the open strategies and on the conversion library asserts that neither runs for an encrypted doc/ppt without a password. Today's empty-text and partial-result shapes must not come back.
- Database and external-API test strategy: not applicable — this library has neither.
