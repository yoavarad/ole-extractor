## Description

ydk task ready is unreliable across this whole repo: three compounding bugs found while running two batches of tasks this session. (1) ydk task done never syncs a completed task's status to 'done' anywhere -- not the task .md frontmatter (T-eeb6684b.md still shows status: in-progress despite PR #4 having merged days ago), not manifest.yaml either by default. The real gate ydk task start/ready actually reads is manifest.yaml's tasks[id].status (see ydk repo: src/ydk/repositories/local/tasks.py check_dependencies(), which reads self._manifest.load() and treats a dep as resolved only if status == 'done') -- but nothing in the task-done flow writes that value, so every dependent task falsely reports 'Deps Met: yes' regardless of whether its dependencies actually merged. This was manually worked around twice this session by hand-editing manifest.yaml's status fields for tasks confirmed merged via git log. (2) .ydk/batch-mapping.json is overwritten wholesale (not merged) by ydk task create-batch, so an earlier batch's slug-to-real-ID mappings (e.g. task-net8-downgrade -> T-eeb6684b) get silently dropped the next time a batch is created, breaking ydk task start's dependency resolution for any task still referencing the lost slug. Recovered once this session from a stage-02-planning report's markdown table since the file wasn't git-tracked (now fixed separately in PR #10). (3) manifest.yaml's dependency lists sometimes retain the old slug (e.g. 'task-net8-downgrade') in OTHER tasks' dependencies arrays even after the referenced task's own entry gets keyed by its resolved real ID (T-eeb6684b) -- the resolution step apparently updates a task's own key but not other tasks' references to it. This makes ydk task ready fundamentally untrustworthy for this repo's whole DAG (65 tasks) without manual cross-checking against real git/PR-merge state task by task, which doesn't scale. Root cause lives in ydk-core (a separate project at C:\Users\yoava\Projects\ydk, not in this repo), so this task's job is: (a) write a one-time remediation pass that walks every task in .ydk/manifest.yaml and .ydk/tasks/*.md, determines TRUE completion state by checking whether the task's branch was actually merged to main (via git log --merges or gh pr list --state merged), and corrects manifest.yaml's status field (and ideally the .md frontmatter status too, for consistency) to match reality; (b) document the three root causes precisely (file/function/line references) in docs/project-rules.md's Known Gotchas so future sessions don't have to rediscover this; (c) do NOT attempt to patch ydk's own Python source under C:\Users\yoava\Projects\ydk as part of this task -- that's a separate repo and a separate decision for the user to make.
