## Description

The pptx text spot-check in the corpus integration test (PR #120, ExtractCorpusManifestTests.cs, not yet merged when filed) compares substrings with whitespace collapsed and never checks slide order, so it would not catch the slide-order bug filed as the pptx slide order task. Strengthen it so that for the pptx samples in samples/manifest.json the test asserts the full expected text per slide, in deck (p:sldIdLst) order, against MainExtractor.Extract output, rather than presence of substrings. The expected per-slide text must come from the manifest (extend the manifest schema with a per-slide list if only a flat bodyText exists) and must be derived from the deck, not from the extractor's output, so the test is a true oracle. Depends on the slide-order fix.
