## Description

Produce one oversized-declared-size sample (a small file whose declared ZIP/CFB internal structure exceeds nesting-depth-guard's caps — a zip/CFB bomb) and one password-protected sample (document-open password or CFB EncryptionInfo/EncryptedPackage stream), each tagged with which format(s) it targets.


## Activity Log
### 2026-09-13T10:19:05Z (UTC)
Both adversarial samples produced and recorded in samples/manifest.json under a new samples/adversarial/ directory. Oversized-declared-size bomb (samples/adversarial/oversized-declared-size-bomb.doc, 2560 bytes, targets doc/xls/ppt): new SampleGenerator.Generators.AdversarialSampleGenerator.BuildCfbSizeBomb() forges a CFB header's FAT sector count (offset 0x2C) to 100000 via OpenMcdf, implying declared ~6.1GB, exceeding nesting-depth-guard's 2GB cap -- verified end-to-end via the real ExtractorOLE CLI, which throws OversizedNestedContentException with the exact declared-vs-limit numbers. Re-ran SampleGenerator/Program.cs's full pipeline (needed to produce the bomb file) which non-deterministically touched unrelated pre-existing sample files (documented pre-existing GUID/timestamp behavior); reverted those via git checkout to stay surgical. All 3 acceptance criteria met.
