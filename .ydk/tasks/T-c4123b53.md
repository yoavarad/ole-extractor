## Description

Implement the open component for legacy .doc via self-compiled NPOI (HWPFDocument), producing FileMetadata sourced from OLE SummaryInformation/DocumentSummaryInformation, registered through the DI dispatch registry.


## Activity Log

### 2026-08-23T04:48:27Z (UTC)
**Blocked (blocked-by-research):** NPOI mainline (self-compiled per T-d6de875f) doesn't provide HWPFDocument for .doc -- it only exists in NPOI's non-SDK-style, .NET-Framework-2.0-only scratchpad/ tree, not even shipped in NPOI's own NuGet package. Blocked on T-bac988f5's decision (port scratchpad vs. alternative library) before this task's acceptance criteria (HWPFDocument-based open component) can be implemented as written.

- 2026-08-23: T-bac988f5 resolved the NPOI-scratchpad blocker. Decision (ADR-004, draft
  pending human sign-off): use `b2xtranslator` (BSD-3-Clause) to convert .doc -> .docx
  in-process, then extract via the existing DocumentFormat.OpenXml path -- not
  `HWPFDocument` as this task's title/AC currently say. FileMetadata (SummaryInformation/
  DocumentSummaryInformation) can be wired now via NPOI's main-tree HPSF/POIFS regardless
  of the body-text decision -- not blocked. This task's AC #1 ("opens via NPOI HWPFDocument")
  needs rewriting to reference b2xtranslator before implementation starts. See ADR-004 and
  docs/research/legacy-doc-ppt-parsing.md for full rationale, including the documented
  fallback (port NPOI scratchpad HWPF, recipe validated by github.com/IllidanS4/npoi) if
  b2xtranslator fails empirical i18n fidelity testing.
