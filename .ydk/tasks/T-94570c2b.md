## Description

Test NPOI's text/metadata extraction against 1-2 real multilingual samples (Hebrew/Arabic/CJK at minimum) on the legacy doc/xls/ppt read path, since this is flagged unverified in ADR-001 and docs/project-rules.md. Must complete before Epic 4 (Legacy OLE Extraction) relies on NPOI's i18n fidelity.


## Activity Log

### 2026-09-02
Ran the empirical test harness added in commit `8b6ae55` (`ExtractorOLE.Tests/Excel/XlsTextExtractorTests.cs`), which round-trips NPOI-written `.xls` fixtures through `XlsTextExtractor.ExtractText` against the multilingual/emoji corpus in `SampleGenerator/Fixtures/MultilingualFixtures.cs`. Initialized the `third_party/npoi` submodule and ran `dotnet test --filter FullyQualifiedName~XlsTextExtractorTests` from `ExtractorOle/ExtractorOLE.Tests`.

Result: **15/15 tests passed**, 0 failed. All 6 script families passed (`SingleScriptFixture_RoundTripsExactly`: Hebrew, Arabic, Persian, Russian, Latin, Cjk) and all 4 emoji fixtures passed (`EmojiFixture_RoundTripsExactly`: EmojiSimple, EmojiFamilyZwj, EmojiSkinTone, EmojiFlagZwj), plus `MultilingualFixture_RoundTripsExactly`, `CombiningCharacterSequence_NotNormalized`, and 3 edge-case tests (empty workbook, no textual content, corrupt bytes). No fidelity gap found for `.xls`.

Updated `docs/project-rules.md` (Known Gotchas) to replace the "unverified" NPOI i18n bullet with the verified `.xls` result (still unverified for `.doc`/`.ppt`, not yet implemented), and added a `## Note (2026-09-02)` addendum to `docs/adrs/001-extraction-library-stack.md` recording the same result, cross-referencing project-rules.md. No new test or source code was written — this was a verification + documentation pass only. Since no fidelity gap was found, no note was added to Epic 4 (`.ydk/epics/E-a7ddf85b.md`) per the task instructions.
