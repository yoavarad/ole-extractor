## Description

Naming mismatch found while writing the corpus integration test (PR #120, not yet merged when filed). For xlsx, images hosted on a WorksheetPart are named slide_image_N by ExtractionHelper.ExtractFirstLayerEmbedded (Phase 2 scan, ExtractorOle/ExtractorOLE/Helpers/ExtractionHelper.cs, prefix chosen by scan phase rather than by container type), while the older multi-embedding xlsx manifest entry (samples/synthetic/multi-embedding/sample.xlsx) and its spec-side expectation use embedded_object_N. The manifest itself is inconsistent: the macro-enabled xlsx sample records slide_image_1 while other xlsx entries record embedded_object_N. The integration test currently ignores the filename prefix for these entries. docs/specs/extraction.md and the SubfileItem entity (.ydk/components/entity/extraction/SubfileItem.yaml) only say FileName is the best-available name and do not prescribe a prefix scheme; note that slide_image is a poor name for a spreadsheet image. Decide the correct scheme from the spec (a neutral name such as embedded_object_N for every OOXML first-layer item, or a documented per-kind prefix), align the extractor or the manifest and spec, and make the test assert the exact name.
