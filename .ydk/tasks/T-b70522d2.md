## Description

Follow-up to ADR-004, which scoped b2xtranslator to .doc/.ppt only and kept .xls on NPOI HSSF
(net8.0-buildable today, zero risk, zero spike needed). User is now asking whether NPOI can be
retired entirely -- route .xls through b2xtranslator too, and confirm the format-agnostic
HPSF/POIFS pieces (metadata + subfile discovery) can be replaced by OOXML-native equivalents
after conversion.

This is a bigger question than "swap the xls body-text library": b2x's Xls module has had zero
research done on it (ADR-004's due-diligence -- symmetric module structure, spec-driven
pedigree, stale-since-2018 risk -- was scoped to Doc/Ppt only), and dropping NPOI fully also
requires confirming subfile/embedded-object discovery still works without POIFS, which today is
format-agnostic and happens independent of body-text parsing.

Include forking b2xtranslator (BSD-3-Clause, unmaintained since 2018) to an org-controlled repo
as part of this task, regardless of the Xls decision -- same "we own any bugs we hit" risk class
already accepted for .doc/.ppt in ADR-004; a fork makes patching/tracking those fixes easy
instead of vendoring a dead upstream directly.

See prior spike: docs/research/legacy-doc-ppt-parsing.md and ADR-004 for the Doc/Ppt precedent
this should mirror.
