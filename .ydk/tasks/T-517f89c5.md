## Description

Implement the open component for legacy .ppt via self-compiled NPOI (HSLFSlideShow), producing FileMetadata sourced from OLE SummaryInformation/DocumentSummaryInformation, registered through the DI dispatch registry.


## Activity Log

### 2026-08-23T04:48:29Z (UTC)
**Blocked (blocked-by-research):** NPOI mainline (self-compiled per T-d6de875f) doesn't provide a working HSLFSlideShow for .ppt -- HSLF exists only in NPOI's non-SDK-style, .NET-Framework-2.0-only scratchpad/ tree as incomplete low-level record classes, not a usable PowerPoint reader, and isn't shipped in NPOI's own NuGet package. Blocked on T-bac988f5's decision (port scratchpad vs. alternative library) before this task's acceptance criteria can be implemented as written.

- 2026-08-23: T-bac988f5 resolved the NPOI-scratchpad blocker. Decision (ADR-004, draft
  pending human sign-off): use `b2xtranslator` (BSD-3-Clause) to convert .ppt -> .pptx
  in-process, then extract via the existing DocumentFormat.OpenXml path -- not
  `HSLFSlideShow`, which does not exist as a working entry point anywhere in NPOI's C#
  scratchpad (confirmed by code search; HSLF there is Model/Record classes with no
  "open file" glue). This task's AC #1 needs rewriting to reference b2xtranslator before
  implementation starts. FileMetadata (SummaryInformation/DocumentSummaryInformation) can
  be wired now via NPOI's main-tree HPSF/POIFS regardless of the body-text decision -- not
  blocked. See ADR-004 and docs/research/legacy-doc-ppt-parsing.md for full rationale and
  the documented fallback (LibreOffice headless conversion) if b2xtranslator fails
  empirical i18n fidelity testing.
