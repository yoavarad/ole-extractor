## Description

Ensure at least one curated sample has 2+ levels of nested embedding (an embedded object that itself contains an embedded object), to exercise the "subfile that is itself a container" behavior from subfile-scope (the outer embedding is one opaque SubfileItem; its own contents are not separately listed).


## Activity Log

### 2026-08-29 - Sample already existed; added the missing test

Investigated `samples/manifest.json` and `SampleGenerator/Fixtures/CuratedSampleSpecs.cs`
before writing anything new: T-6f033869 had already authored three curated
samples with genuine 2-level nested embedding (`meeting-minutes-boardroom.docx`
docx->xlsx->png, `project-status-report.xlsx` xlsx->docx->png,
`product-launch-deck.pptx` pptx->xlsx->png), each recorded in the manifest with
`expectedSubfileCount: 1` (the outer embedding only - the inner PNG is not
listed). So both acceptance criteria were already satisfied at the data level,
but `verifiedBy` was `null` for all three - no test actually exercised the
non-recursive-unpacking rule against these samples.

Added `ExtractorOle/ExtractorOLE.Tests/MultiEmbedding/CuratedNestedEmbeddingSampleTests.cs`
with two tests (docx-host and pptx-host, the two nested curated samples
manifest.json marks `detectable: true`) that generate the real curated sample
bytes via `CuratedSampleSpecs.BuildMeetingMinutesBoardroom()` /
`BuildProductLaunchDeck()`, run them through the real `WordOpenStrategy` /
`PowerPointOpenStrategy`, and assert: exactly one first-layer subfile, its
bytes equal the untouched inner xlsx package (proving it wasn't unpacked), and
no `.png` / inner-chart-named entry appears anywhere in the result. Skipped
the third nested sample (`project-status-report.xlsx`, xlsx-hosted) because
manifest.json already documents it as `detectable: false` - a pre-existing,
out-of-scope gap where `ExtractionHelper.ExtractFirstLayerEmbedded` doesn't
yet scan `WorksheetPart` for xlsx hosts (same known gap noted on the
multi-embedding xlsx sample); asserting against it here would just encode a
known-broken expectation.

Updated `samples/manifest.json`'s `verifiedBy` field for the two now-tested
entries to point at the new test methods.

`dotnet build` (Release) and `dotnet test` (Release) on the full solution
both pass clean: 57/57 tests (55 pre-existing + 2 new), 0 warnings/errors.
