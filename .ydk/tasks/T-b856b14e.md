## Description

Replace the NotSupportedException placeholders in the legacy-format generators of SampleGenerator so it can author valid legacy .doc, .xls and .ppt files. Unblocks T-07571b32 (generate remaining 10 legacy-format samples).

Context refs: docs/adrs/001-extraction-library-stack.md, docs/adrs/004-legacy-doc-ppt-parsing.md; done tasks T-bac988f5, T-b70522d2 (library research), T-c4123b53 (doc open component), T-517f89c5 (ppt open component).

Step 1 - spike (time-boxed): determine which library can WRITE legacy .doc and .ppt body content.
- b2xtranslator (ADR-004) is believed to be a reader/converter to OOXML, not a binary writer - VERIFY this.
- .xls via NPOI HSSF is already proven (15/15 Unicode fidelity).
- Candidates to evaluate: NPOI (self-compiled per ADR-001; HWPF/HSLF write support), OpenMcdf + hand-built streams, other OSS options.
- Record the outcome. If it changes or extends ADR-001/ADR-004, add a NEW ADR under docs/adrs/ rather than editing the accepted ones.

Step 2 - implement:
- Replace the NotSupportedException placeholders in SampleGenerator/Generators/DocSampleGenerator.cs (~l.20-24), SampleGenerator/Generators/XlsSampleGenerator.cs (~l.18-22) and SampleGenerator/Generators/PptSampleGenerator.cs (~l.18-22).
- Add the required package/project references to SampleGenerator/SampleGenerator.csproj (currently no NPOI/b2xtranslator).
- Round-trip: each generated file must be readable by ExtractorOLE's corresponding open strategy (doc/xls/ppt).
- Unicode fidelity must be checked for .doc and .ppt (only .xls verified so far, 15/15).
