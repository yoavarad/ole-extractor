## AI Analysis
### Patterns
- Scope grew mid-epic. The epic started as OOXML Agile/Standard plus xls; the legacy research (docs/research/legacy-encryption/, task 395) added doc and ppt decryption (stories 390-394, ADR-013) and superseded task 383.
- Same skeleton as epic 301: request/exception surface (372) and samples (373-375, 397) first, then decryptors and probes, then wiring into Extract (379, 406, 407), then manifest-driven three-way and confidentiality tests (386, 408, 384, 385, 409), then docs (387, 411).
- Legacy decryption reuses the existing pipeline: decrypt, rebuild a plain compound file (PlainCompoundFileBuilder), swap the input. No parser changed for encrypted input.
- Gated tasks (412, 414, 415, 413) waited on fork fixes in npoi (#197, #198) and b2xtranslator (#156, #159, #160, #161) and were closed after re-pins (441, 470, 476).
- Unverifiable edges were recorded instead of guessed: G1-G5 in samples/manifest.json `$encryptedTestGaps`, each with coveredBy tests and a blockedOn reason.

### What went well
- Every encrypted fixture is tested three ways (no, wrong, correct password) against an unencrypted twin, leaf by leaf, for both Extract and DetectMimeType.
- Sentinel-password tests cover every password-path outcome, so the password cannot leak into messages, logs or results.
- The CI-mirror build with `-p:CiWarningsAsErrors=true` caught analyzer errors before merge: CA1861 in #427 and CA1711 in #472 (local Debug builds only show these as warnings).
- The Linux CI leg caught a test that failed only on ubuntu-latest in #464 (Windows passed). The fix made the hello-fixture text assertions newline-agnostic.
- Measured numbers, not estimates, went into the PRs and ADR-013 (allocation runs, BenchmarkDotNet tiers, b2xtranslator text-parity output in #473).

### What went wrong
- Clean-merging sibling PRs still broke main. #457 (three-way tests expecting empty CryptoAPI xls metadata) and #458 (reading that metadata) each passed CI alone; main CI failed at aa211cd and #460 fixed it.
- #436 (PlainCompoundFileBuilder) merged with no recorded reviewer pass and no allocation measurement. The cost surfaced later in #464: encrypted ppt Extract allocated about 29x its input against an 8x target. The user accepted #436 as it was.
- #468 cut allocation from 29.04x to 23.41x (cryptoapi-proc2356.ppt, GC.GetTotalAllocatedBytes precise) and Build alone from 9.34x to 3.70x, but missed the 8x target. Even a free Build would leave Extract near 19.7x. The miss was accepted and recorded in ADR-013.
- Task 353 was unblocked on the belief that ydk 1.11.1 derives the dotnet-format budget from the manifest timeout (#442 dropped the override). It does not. #449 restored the override.
- `ydk task done` does not commit (known), and for #473 it opened the PR against the re-pin branch (chore/470-...) instead of main. The base was changed to main by hand.
- ydk LLM checkpoints have no API key to answer them here: 108 requests since 2026-11-10 (70 spec-review, 20 layer-b-scan, 18 complexity) in .ydk/llm/requests. Task agents stopped at them and the main session answered them.
- The npoi re-pin #477 was redundant for task 413: the npoi#198 XOR primitives (fork PRs #204, #205) were already in the old pin.
- No Word-authored XOR .doc fixture was found. Third-party fixtures (openwall/john-samples and nono/xor_me) were accepted instead, with licences still pending.

### Template suggestions
- Batch-merge checklist: after merging a batch of sibling PRs, pull main, run the CI-mirror build and the full test suite before starting the next batch; record the result on the batch.
- Performance-sensitive task template: target ratio, measurement method (GC.GetTotalAllocatedBytes precise, BenchmarkDotNet tier), real before/after output pasted in the PR, and what happens if the target is missed.
- Gated task template: the upstream issue, the pin that contains the fix (verified with `git merge-base --is-ancestor`), and the test that turns from skipped/expected-fail to pass.
- Unblock note: quote the upstream change (commit, release note body or test) that proves the blocker is gone, not only a title.

### Rule suggestions
- Build and test main after every batch merge; parallel PRs that touch the same manifest entry or behaviour need to be merged and rebased in sequence.
- Read the warning count of the CI-mirror build (`-c Release -p:CiWarningsAsErrors=true`), not only "Build succeeded".
- Tests that compare extracted text must be newline-agnostic or normalise line endings, so they pass on Linux and Windows.
- No PR that adds a hot-path allocation (buffers, file-system copies) merges without a reviewer pass and a measured allocation figure.
- After `ydk task done`, check `gh pr view --json baseRefName,files` and fix the base and the diff before reporting the PR.
- Every new worktree runs `git submodule update --init --recursive` before building.
- Before a re-pin, check whether the needed commits are already in the current pin.

### Follow-ups
- The b2xtranslator EncryptedDocumentException catch on the text-extraction path in MainExtractor always throws PASSWORD_PROTECTED, even when a password was supplied (the open path gives INVALID_PASSWORD). It is only reachable if the legacy-encryption guard is bypassed.
- THIRD-PARTY-NOTICES has no b2xtranslator notice.
- Known gaps G1-G5 (`$encryptedTestGaps` in samples/manifest.json) remain blocked on real authored fixtures.
- Licences of the third-party XOR .doc fixtures (john-samples, xor_me) are pending; the repo owner will resolve them.
- The remaining encrypted ppt allocation (23.41x) is mostly outside PlainCompoundFileBuilder.Build (decrypt, open and downstream extraction); it needs a separate task if 8x is still wanted.

### Summary
Epic 362 shipped password-based decryption for all six formats: OOXML Agile (ported from NPOI with an added HMAC integrity check) and Standard, xls RC4/CryptoAPI/XOR, doc BinaryRC4/RC4 CryptoAPI/XOR and ppt RC4 CryptoAPI. Encrypted doc and ppt are now detected before parsing instead of returning silent partial results. It closed 39 tasks under the epic's stories plus 9 supporting spec, re-pin and fix tasks (383 was superseded), with ADR-012 and ADR-013 Accepted. The test design (three-way tests against twins, sentinel-password confidentiality, recorded known gaps) held up. The main problems were process ones: a semantic break on main from parallel PRs, a merge without review that hid an allocation cost, a premature unblock, and ydk friction (no auto-commit, wrong PR base, LLM checkpoints that need a human).
