## AI Analysis
### Patterns
- Silent-failure removal dominated the sprint: tasks 286-288, 287, 289, 291 replaced swallowed exceptions and empty results with surfaced failures, then locked it in with CA1031.
- Resource-bound hardening of untrusted input recurred across OOXML and CFB paths: inflated-byte caps (276), declared-size allocations (277), Content_Types byte cap and DTD ban (278), name sanitization (279), ExtractManyAsync memory (297).
- Tooling exit-code honesty was a cluster: stress, benchmark and batch tools returning zero on failure (292, 293, 339) and CI not verifying samples or manifests.
- Test-quality debt was paid down in bulk: removing wall-clock and cross-test dependence (294), closing assertion and coverage gaps (295), strengthening the failed-open stream test (338).
- Small input-validation and overflow fixes (281 non-positive limits, 285 EditTime overflow, 284 metrics and tag cardinality) followed one pattern: validate at the boundary and bound unbounded values.

### Template suggestions
- Hardening task template: threat/untrusted input, the bound or cap chosen, the failure behavior (typed exception vs result), and a regression test with an adversarial sample.
- Catch-narrowing task template: list the catch sites, the exceptions expected at each, how the cause is preserved (inner exception or logged), and the analyzer rule enforced.
- Tool exit-code task template: define success/failure conditions, expected-failures list format, and a CI step proving a non-zero exit on injected failure.
- Test-determinism checklist: no wall-clock sleeps, no shared static state, explicit synchronization primitives, and each test runnable in isolation and any order.

### Rule suggestions
- Never swallow exceptions or return empty results on failure; surface the error and preserve the cause, enforced by CA1031 as an error.
- Every parser of untrusted input must enforce a cap on bytes actually read or inflated, never trusting declared sizes, with a test using an oversized sample.
- Any CLI or CI tool must exit non-zero on failure, and CI must fail if required inputs such as manifests or samples are missing.
- Tests must not depend on wall-clock timing or on other tests' state; use deterministic signals instead of delays.
- Public APIs must validate limit and option parameters at entry and reject non-positive or overflowing values.

### Summary
Sprint 270 closed 25 tasks centered on robustness hardening of the OLE/OOXML extractor: eliminating silent failures, capping resource use on untrusted input, and making tools and CI report failures honestly. A secondary thread cleaned up flaky and weak tests and fixed metadata correctness bugs. The recurring themes suggest codifying templates and analyzer-enforced rules so these classes of defect are caught at authoring time.
