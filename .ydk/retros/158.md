## AI Analysis
### Patterns
- Performance and memory optimization was the dominant theme: nearly half the tasks targeted eliminating redundant work (open-once/parse-once in #167, #168, #201, #202), removing temp-file IO (#169, #190), and avoiding double copies (#170).
- A repeated 'hand the already-opened object downstream' refactor was applied per format (OOXML #167, xls #201, ppt #202, ppt conversion #168), i.e. the same fix applied serially to each format strategy.
- Stream-based input migration was a coherent epic: spike (#174) followed by implementation across the request/OOXML path (#192), preflight/detectors (#193), and legacy CFB parsers (#194).
- Measure-first workflow: instrumentation (#163), profiling guide (#164), and nightly benchmarks (#166) came before or alongside optimizations, and benchmarks then exposed bad data (#165 doc-100mb at 37ms, #185 ppt padding), which led to output sanity checks.
- The same benchmark defect (padding or non-real content) recurred across formats (#165 doc, #185 ppt), so it was found by format rather than systematically.
- CI speed-up was a cluster of small independent tasks (#175-#177, #178, #180): NuGet caching, single build, parallel format job, shallow submodules and caching, docs-only skip.
- Concurrency hardening followed the parallelism features: thread-safe static counters (#172), batch API with bounded parallelism (#173), and re-enabled xunit parallelization (#179).
- Third-party and submodule maintenance generated reactive work: b2xtranslator repin and .gitmodules branch fix (#219), the ImageSharp NU1902/NU1903 audit failure from a transitive NPOI dependency on main (#210), and the net8.0 to net10.0 retarget (#214).
- Temp-file leaks and double work in b2xtranslator (#169, #190, #168) suggest the forked dependency is a recurring source of performance defects and needs upstream/fork discipline.
- Late-sprint tasks (#210, #214, #219) are higher-numbered maintenance and unblocking items, indicating main was broken or drifting by dependency audit and framework changes.

### Template suggestions
- Open-once refactor checklist: identify the open strategy, pass the opened document/workbook/filesystem to the extractor, remove the second open, add a test that asserts a single open (counter or mock), and record before/after benchmark numbers.
- Benchmark sample validation checklist: for each format, verify the sample has real content (non-padding), assert minimum extracted text length or entropy, and compare timing against a plausible range.
- Stream-migration task template: list affected layers (request, preflight, detectors, open strategies, parsers), define LOH/allocation acceptance criteria, and add a large-file memory test.
- Performance task template: baseline metric, hypothesis, change, post-change metric (time, allocations, LOH), and the benchmark/profiler command used.
- CI optimization task template: current job duration, change, expected savings, and a cache-hit/miss verification note.
- Dependency/submodule bump template: reason, pinned commit or version, .gitmodules branch check, audit (dotnet list package --vulnerable) result, and full build/test confirmation.
- Concurrency-safety checklist: enumerate static/shared mutable state, thread-safe replacement, and a concurrent Extract() stress test.

### Rule suggestions
- Any performance PR must include before/after benchmark or allocation numbers, and benchmark output must pass sanity checks (non-trivial extracted content) before results are trusted.
- Benchmarks must assert output validity for every supported format (doc, ppt, xls, docx, etc.) rather than being fixed one format at a time.
- Do not create temp files in conversion paths; use in-memory streams, and add a test or analyzer check that no temp files remain after Extract().
- Open strategies must pass the opened document object to extractors; extractors must not reopen or reparse the input.
- No new static mutable state without thread-safety; any new shared state requires a concurrent Extract() test.
- Run a scheduled (weekly or nightly) dependency vulnerability audit so NuGet advisories like NU1902/NU1903 are caught off main, and pin or override vulnerable transitive packages explicitly.
- Submodule changes must pin to a merge commit on the fork's main and verify .gitmodules branch matches in the same PR.
- Schedule the target framework retarget (net8.0 to net10.0) as a planned item with a compatibility checklist, not a reactive fix.
- Spikes (like #174) must end with a written decision and follow-up tasks so implementation tasks (#192-#194) are linked to them.
- CI changes must report measured runtime before and after, and docs-only skip filters must be reviewed to avoid skipping required checks.

### Summary
Sprint 158 completed 27 tasks focused on making extraction faster, leaner, and more concurrent. Work centered on eliminating redundant opens/parses and temp-file IO, migrating to stream-based input across the request, preflight, and legacy CFB paths, and adding batch extraction with thread-safety fixes. Observability (ActivitySource/Meter instrumentation, profiling guide, nightly benchmarks) supported the optimizations and exposed invalid benchmark samples (doc, then ppt). A cluster of CI improvements (caching, single build, parallel format check, docs-only skip, xunit parallelism) reduced pipeline time, and late maintenance fixed the ImageSharp audit failure, the net10.0 retarget, and the b2xtranslator repin. The main takeaways are to standardize open-once and benchmark-validity checks, plan dependency and framework maintenance proactively, and treat concurrency and temp-file hygiene as enforced rules.
